# Golden sets of the LLM benchmark

Used only by the manual benchmark (`uv run python -m tuttitrip_worker.bench`,
see `docs/benchmarks/README.md`). No test of the normal pipeline reads them for
a real model; `tests/test_bench.py` checks their shape.

Every case is a directory with `examples.jsonl`, one JSON object per line:

| Field | Meaning |
| --- | --- |
| `id` | Unique in the case, `pl-NN` or `en-NN`. |
| `lang` | `pl` or `en`: the language of the input. |
| `tags` | Why the example is there (`easy`, `injection`, `conflict`, `missing`, ...). |
| `input` | What the model gets (see below). |
| `expected` | The reference answer, in the shape the scorer of the case reads. |
| `notes` | Why the reference is what it is (for people; the judge never sees it). |

| Case | Input | Reference | Scored by code | Scored by the judge |
| --- | --- | --- | --- | --- |
| `extract_offer_evidence` | `offer`, `requirements` (`key`, `label`) | quotes with a verdict per key | state per key, reference quotes covered | relevance of the quotes |
| `offer_verdict` | derived from the above | verdict per quote | every verdict | none |
| `parse_pasted_plan` | `text`, `city_slug` | items with day, times, price, transport, address | recall, precision, fields | address and city |
| `generate_trip_plan` | `request` | destination, days, highlight ideas, criteria | destination, days, list size | fit of the highlights |
| `parse_expense_text` | `text`, `locale` | amount, currency, payer, included, excluded, description | all but description | description |
| `read_receipt` | `image` (PNG in `images/`) | total, currency, date, merchant, lines | all but item names | item names |
| `match_places` | `name`, `quote`, `places` (the city's catalog) | `place_id` or `null` | the id | none |

Rules for the data:

- Everything is invented or public knowledge: no real people, no real receipts, no
  real card or tax numbers. Names of people are common first names only.
- A reference field that is `null` means "the source does not say": the model must
  leave it empty too (never guess an amount, a date or a currency).
- Names are kept as written in the input (`bez Ani` gives `Ani`).
- Every example is hard in a way its `tags` and `notes` state; add a new one with a
  tag that says why, not a copy of an easy one.
- `read_receipt` images and answers are generated by
  `scripts/make_golden_receipts.py` (fictional merchants); rerun the script to
  change them instead of editing the JSON by hand.
- `extract_offer_evidence` quotes in `expected` must be verbatim spans of the offer
  (a test checks it).

The common rubric of the judge is `rubric.md`; a case can add its own
`<case>/rubric.md`.
